# Product media, description and pagination

Implemented and verified on 2026-10-18 against XAMPP MariaDB and Laravel's existing API architecture.

## Schema and product contract

Only these additive migrations were executed on `karem_altin`:

- `2026_10_18_000001_add_description_to_products_table.php`: nullable `products.description TEXT`.
- `2026_10_18_000002_create_product_images_table.php`: `id BIGINT UNSIGNED` auto-increment primary key; required, indexed `product_id BIGINT UNSIGNED` referencing `products.id` with restricted deletion; required `image_path VARCHAR(255)`; nullable `created_at` and `updated_at` timestamps.

Both have rollback methods. No historical migration or seeder changed. No database reset was performed.

Description accepts null, Arabic/English and multiple lines, with a 65,535-byte TEXT capacity check. Creation without it stores null. PATCH omission preserves it; explicit null or empty input clears it through existing request normalization.

Product representations include `description` and `images` in list, detail, create, update, status, category details and grouped catalog responses. Missing media returns `images: []`. Images are ordered by ID and eagerly loaded; the catalog does not load recipes. Order snapshots and stock rules are unchanged.

Uploads use the existing `public` disk and relative paths `products/{product_id}/{uuid}.{detected_extension}`. The API returns image IDs and URLs generated by `Storage::disk('public')->url(...)`, never local filesystem paths. Example shape:

```json
{"description": null, "images": [{"id": 15, "url": "https://your-configured-host/storage/products/25/generated-name.png"}]}
```

The hostname above is illustrative; actual URLs follow the existing disk configuration and `APP_URL`.

Validation permits up to 10 actual JPEG/PNG/WebP uploads per request, each at most 5 MB. SVG, remote URLs, invalid content and unsupported types are rejected. UUID filenames avoid client filenames and traversal. Updates append images; omitted images preserve existing files. No deletion/reordering endpoints were added.

Database operations run in a transaction. On upload or database failure, all attempted new file paths are deleted, including partial writes; existing images remain untouched. Automatic transaction replay is disabled when uploading files. Filesystem deletion failure is surfaced as an error. Process crashes or unavailable storage cannot provide cross-system atomicity; no recovery queue was introduced.

## Multipart usage and Postman

Use `POST /api/products`, multipart form-data, with existing required product fields and optional `description` (Text) and repeated `images[]` (File).

For updates, send **POST** `/api/products/{product}` with `_method=PATCH`, optional `description`, and optional repeated `images[]`. Laravel routes this to the existing PATCH route. Keep `Accept: application/json` and bearer authorization; let the client generate the multipart Content-Type boundary.

Updated the existing `docs/postman/OrderAPI.postman_collection.json`, retaining its folders and 69 HTTP requests. Create contains three disabled optional file fields; update contains one. Enable them and select local files for manual upload runs. Optional pagination Params and media/pagination assertions were added. JSON import/execution succeeded. The automated Newman run used disabled file fields; actual uploaded file content and method-spoofed append behavior were tested in Laravel Feature tests using fake public storage.

## Pagination audit

All paginated responses use native `data`, `links`, `meta`, SQL pagination, deterministic ordering and retained query parameters. Defaults match the existing orders/print-jobs convention: page 1, **20 items**, allowed `per_page` 1–100, integer `page >= 1`. Invalid inputs return validation errors; valid empty pages return normal empty data and populated pagination metadata.

| GET endpoint | Added/preserved | Default per_page | Existing filters/behavior preserved |
|---|---|---:|---|
| `/api/products` | Added | 20 | item_type array, category_id, department_id, is_active, search |
| `/api/inventory` | Added | 20 | item_type, is_active, search, low_stock_only |
| `/api/inventory/movements` | Added | 20 | product_id, transaction_type, direction, from, to; newest first |
| `/api/employees` | Added | 20 | role, is_active, search |
| `/api/expenses` | Added | 20 | from, to, status, created_by, search |
| `/api/orders` | Preserved | 20 | order_status, payment_status, employee_id, table_id, search, from, to; ownership scope |
| `/api/print-jobs` | Preserved | 20 | status, job_type, printer_id, department_id, order_id, from, to |
| `/api/printers` | Added | 20 | Existing list had no query filters |
| `/api/tables` | Added | 20 | status, is_active and active_order response retained; existing list had no query filters |
| `/api/settings` | Added | 20 | Existing list had no query filters; unique key ordering |
| `/api/reports/top-products` | Added | 20 | from, to, limit; full aggregation and ranking before pagination |

The top-products `limit` remains a total ranked-result cap (default 10, maximum 100), applied inside a subquery before pagination. Dashboard Top 5 behavior remains unchanged.

Intentional exceptions: categories; departments; category-grouped employee catalog; all individual detail endpoints (including nested category products); dashboard summary and its fixed arrays; financial report and its daily breakdown; nested product images and recipe ingredients. The grouped catalog still returns all eligible products, so a future large catalog may need a separately designed API contract.

## Deployment and compatibility

- Run `php artisan migrate` on other environments and `php artisan storage:link` if the link is absent. The local link was created successfully without overwriting one.
- Configure `APP_URL` to the externally reachable origin and keep the public disk directory writable. Serve uploaded files as static content.
- Local PHP reports `upload_max_filesize=40M`, `post_max_size=40M`, `max_file_uploads=20`. Application validation still enforces 5 MB per image. To accept ten maximum-sized files together, configure the deployed web PHP/proxy request limit above 50 MB plus multipart overhead (for example 64 MB). PHP configuration was not changed.
- Frontends using previously unpaginated administrative lists must follow `links`/`meta` to retrieve later pages. Category/department selectors and grouped catalog contracts are unchanged.
